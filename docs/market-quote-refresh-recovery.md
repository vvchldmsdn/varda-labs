# 최신 시세 조회와 수집 대기 복구

## 발생 조건

KIS 공용 큐는 과거 시세와 실시간·환율 요청을 같은 실행기로 처리한다. 실시간 요청의 우선권이 대기 시간 30초에 불과해서, 수 시간 먼저 들어온 과거 시세가 항상 먼저 선택됐다. 과거 시세 실패는 실행을 중단하고 재시도해도 최초 대기 시각을 유지하므로 새 시세가 계속 밀릴 수 있었다.

일반 KIS 실행기는 실시간·환율 두 번, 과거 시세 한 번 순으로 우선 선택한다. 해당 종류에 준비된 작업이 없으면 다른 종류를 선택한다. 실패한 KIS 재시도는 다음 실행 가능 시각을 대기 순서에 반영한다. 제공사 예산, 토큰 보호, 작업 잠금, 실패 시 중단과 별도 history/raw/Twelve Data 범위는 유지한다. 제공사 장애·예산 부족까지 일정 처리량을 보장하지는 않는다.

## 화면 연결

기존 홈·오늘 변동과 베타 홈이 공통 `PortfolioRefreshButton`을 사용한다. 신규 원장·USD 화면도 실제 조회 시각으로 갱신 컨트롤을 제공한다. 페이지를 옮긴 뒤 같은 5분 구간으로 돌아와도 대기 작업 확인을 다시 시작한다. 탭 전체의 저장소 표식으로 새 화면의 확인을 생략하지 않는다.

좁은 화면은 종목 추가를 기존 전체 메뉴에서 제공하고 베타 전환을 아이콘으로 줄여 시세 갱신·분석 통화가 겹치거나 잘리지 않게 한다. 원장 복귀 화면에서도 390/320px 가로 넘침, 상단 요소 겹침, 통화명 잘림을 함께 검사한다.

동시 요청은 클라이언트에서 합치고 서버가 실제 보유 종목과 캐시 신선도를 검사한다. 화면 방문이나 수동 버튼은 새 시세를 강제로 중복 수집하지 않는다. 대기 상태는 기존 10초 간격·최대 2분 확인과 Server Component 재조회로 이어진다. 예시·미연결 화면에서는 운영 수집을 시작하지 않는다.

## 검증

- `tests/market-collection.test.mjs`: 실제 큐와 실행기에서 과거 시세 17건 실패가 신규 시세·환율 15건을 막던 조건, 우선 선택·대체 선택, 제한 시 중단, 전용 수집 범위.
- `tests/portfolio-refresh-lifecycle.test.mjs`: 기존·신규 원장·USD 화면 연결, 페이지 복귀, 동시 요청 결합, 대기 확인, 숨김·종료 시 정리.
- `scripts/reliability-fullapp-cases.mjs`: 실제 Next 베타 화면에서 진입·대기 확인·수동 갱신과 1440/390/320px 표시. 외부 공급자 응답만 합성하며 금융 기록과 렌더 경로는 실제 격리 앱을 사용한다.

운영 복구는 기존 관리자 API로 공용 시세·환율만 갱신한다. 거래·현금·보유 기록, 과거 수익률, 기준 스냅샷을 현재 가격으로 덮어쓰지 않는다. 갱신 시각과 시장 관측 시각은 다르며 휴장 중 최신 조회가 새로운 체결 가격을 뜻하지 않는다.
