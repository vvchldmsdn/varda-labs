# 추가투입 진행 흐름

기존 화면과 `/beta`에서 목표 설정, 계산·저장, 실제 매수 연결, 재조회를 같은 경로로 이어간다. 금융 계산과 원장의 권위는 기존 엔진과 소유자 검증 API에 둔다.

## 두 계산의 구분

- **보유 기반 계획**(`/additional-contribution/plan`): 매도 제외와 보유 현금 사용을 포함한 전체 배분을 기존 `NativeContributionPlanner`로 계산·저장한다. 저장한 결과는 당시 기준으로 다시 연다. 이 기록 자체에 거래 귀속 기능을 추가하지 않는다.
- **새 투자금 배분 비교**(`/additional-contribution/compare`): 동일 투자금의 비율 매수와 조정 매수를 기존 비교 엔진으로 계산한다. 저장은 미래 시나리오 입력이 아닌 당시 배분·진입 가격을 보관한다.
- **배분안·매수 연결**(`/additional-contribution/tracking`): 저장한 비교를 먼저 읽는다. 새 계산의 목표·시세가 부족해도 저장 목록은 별도로 조회한다. 계좌별 원장에서 체결을 기록한 뒤 해당 배분안으로 복귀하고, 사용자가 거래를 선택해 연결한다.

보유 기반 계획에 예상 매도와 현금이 포함될 수 있으므로 두 결과를 동일한 추천으로 표시하거나 거래를 자동 귀속하지 않는다. 저장·연결은 주문 실행이 아니다. 기존 거래, 현금, 계산 공식, DB 스키마 및 쓰기 권한을 변경하지 않는다.

## 상태와 이동

공통 `ContributionNextSteps`, `ContributionJourneyNav`와 `contribution-journey.ts`가 양쪽 화면의 진입·복귀 주소를 구성한다. 목표 설정으로 이동할 때 현재 투자금, 투자금 통화, 평가 통화, 현금 사용, 매도 제외 또는 비교 시나리오 입력을 유지한다. 새 계좌를 선택하면 이전 계좌의 매도 제외 선택은 이월하지 않는다.

체결 기록 복귀에는 기존 허용 경로·필드 검사와 `#cairn-return`을 사용한다. 배분안 ID는 복귀할 목록 항목을 선택하는 힌트이며 원장 쓰기 권한이 아니다. 원장 저장 후에도 복귀 주소를 유지한다. 선택한 배분안이 없거나 조회에 실패하면 그 상태를 명시하고 다른 기록의 성과로 대체하지 않는다.

새 보유 기반 계획 화면은 서버에서 확인한 세션의 불투명 키로 클라이언트를 구분하며 사용자 ID를 렌더 입력에 노출하지 않는다. 사용자 변경 재조회 시 이전 사용자의 계획·조회 상태를 재사용하지 않는다. 비교 기록의 연결은 기존 세션 키, revision, 중복 귀속 검사 및 저장 기준 불변 제약을 사용한다. 디자인 미리보기는 실제 보유 기반 계획 화면을 연결하지 않으며 직접 접근도 인증·포트폴리오 조회 전에 중단한다.

## 검증 입구

- `tests/contribution-journey.test.mjs`: 복귀 주소, 통화·조건 구분, 정확한 저장 투자금 재구성, 계좌별 목록 조회와 실패 상태.
- 기존 비교·성과·저장소·계획·복귀 테스트: 금융 계산과 저장 제약 회귀.
- `scripts/reliability-contribution-journey-ui-cases.mjs`: 기존 disposable full-app runner에서 목표 왕복, 배분 저장, 기존/베타 원장 매수, 수동 연결, 새로고침, 화면 너비별 검증. 운영 DB 및 실제 사용자 로그인 상태를 사용하지 않는다.

실제 외부 로그인 검증은 합성 로그인 경계를 사용하는 앱 검증과 별도로 보고한다.
