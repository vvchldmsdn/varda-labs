# 해결 안내와 입력 복귀

목표가 없거나 자료를 확인할 수 없을 때 `RecoveryNotice`가 원인에 맞는 다음 행동을 제공한다. 원본 화면과 베타가 같은 컴포넌트를 사용한다.

- 목표 정책 없음·보유 구성 변경 → 목표비중 설정
- 보유 자료 없음 → 해당 범위의 보유 관리
- 가격·환율·관측 이력 부족 → 보유종목의 분석 데이터 준비 상태
- 거래 근거 부족 → 계좌를 선택한 거래 원장
- 저장 평가 기록 부족 → 저장 기록 확인. 현재 원가 수정으로 과거 수익률을 생성하지 않는다.
- 조회 실패·무결성 충돌 → 현재 입력을 유지한 재조회

수학 계산 불가, 지원하지 않는 경제 모형, 단일 종목의 독립 위험 분석은 자료 수집으로 해결된다고 약속하지 않는다. 관리 기능이 비활성인 베타와 예시 화면에는 관리 이동을 제공하지 않는다.

`recovery-navigation.ts`는 앱 내부 경로와 표시 입력만 허용한다. 출발 주소는 목적지의 `#cairn-return=` fragment에 들어가며 목적지 서버 쿼리에는 포함되지 않는다. 보존하는 것은 금액·통화·계좌 범위·매도 제외·분석 기간 등의 사용자 입력이다. 읽기 영수증, 조회 세대, 계산 결과, 인증 정보는 복귀 근거로 재사용하지 않는다.

관리 과정의 중간 링크는 `RecoveryJourneyLink`, 저장 후 같은 관리 화면을 다시 읽는 이동은 `carryRecoveryFragment`를 사용한다. 완료 후 `RecoveryReturn` 또는 `RecoveryBackLink`로 원래 작업에 돌아온다. 베타 복귀에는 새 조회 세대를 발급한다. 각 목적지의 기존 로그인·소유권·입력·저장 검증은 그대로 적용된다.

히스토리는 실제 관측 날짜가 있는 복귀와 날짜 없는 보기 복귀를 구분한다. `_historyView*`는 기간·지표만 복원하며 날짜나 가격을 만들지 않는다. `_nativeView` 역시 제한된 표시 조건으로만 사용한다.

검증은 `tests/recovery-*.test.mjs`와 `scripts/reliability-recovery-ui-cases.mjs`에서 수행한다. 후자는 기존 격리 PostgreSQL 및 실제 Next 앱에서 목표 설정 왕복, 성공 후 복귀, 단일 GET 실패 후 재시도, 자료 확인 경로와 모바일 화면을 검증한다. 운영 계좌에 시험 거래를 기록하지 않는다.
