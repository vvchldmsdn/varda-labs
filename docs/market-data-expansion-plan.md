# 해외 사용자와 시세 사용량 보완안

검토일: 2026-09-09. 이 문서는 향후 설계안이며, 공급자·통화·사용량 정책을 변경하거나 새 서비스를 구매한 것은 아니다.

## 해외 사용자

한국시간 오전 7시 마감은 서비스 기록의 기준으로 유지할 수 있다. 다만 UTC 수집 시각, 거래소 현지 거래일, KST 서비스 기록일을 별도 필드와 의미로 다뤄야 한다. 화면의 현지 시간 표시는 이 기록 기준을 바꾸지 않아야 한다. 오늘의 잠정 평가액은 확정된 과거 스냅샷과 구분한다.

| 보완할 부분 | 권장 방향 |
| --- | --- |
| 원화 중심 | 언어와 별개로 사용자별 평가 통화를 선택. 거래 통화·원래 거래금액은 보존하고 날짜별 FX로 표시 통화만 환산. 과거 원화 기록에 현재 환율을 곱해 달러 수익률로 가장하지 않기. |
| 한국 상품 중심 | 기본 비교 종목·설명 사례·계좌 유형을 사용자 보유시장에 맞게 선택. KODEX·ISA·IRP를 전 세계 기본값으로 강제하지 않기. |
| 종목 식별 | ticker만으로 합치지 않고 거래소/MIC·통화·자산 종류를 식별. ISIN과 공급자별 코드는 별도 매핑. |
| 공급자 한 곳 의존 | 국내 시세, 미국/기타 해외 시세, FX, 수정주가·기업행위를 공급자 어댑터로 분리. 범위·지연·가격 종류·시각을 반환하는 동일한 내부 계약 사용. |
| 데이터 신뢰도 | 실제 체결 시각과 수집 시각, 실시간/지연/종가, 원시가격/수정가격을 표시. 소스가 바뀌면 같은 기준인지 검증하고 검증 전에는 단순 연결하지 않기. |

공급자 후보는 거래소 범위보다 **외부 사용자 표시 권한**, 수정주가/배당/분할, 과거 FX, 지연 허용 범위, 장애 대응과 비용을 먼저 비교한다. 예를 들어 Twelve Data는 개인용과 사업용 권한을 구분하고 외부 재배포에 별도 계약을 요구한다. 후보 예시이며 구매 추천이나 사용권 확보를 뜻하지 않는다. [공식 사용 안내](https://support.twelvedata.com/en/articles/5332349-commercial-and-personal-usage)

한투 공식 제휴 안내는 제3자 서비스의 제휴 대상과 시세 정보이용계약 조건을 별도로 설명한다. 일반 개인용 키를 확보했다는 이유만으로 공개 서비스의 재배포 권한이 확보됐다고 가정하면 안 된다. 실제 서비스 형태와 대상 거래소를 명시해 공급자에 확인한 뒤 선택해야 한다. [한투 제휴 안내](https://apiportal.koreainvestment.com/provider-info)

## 다중 사용자와 호출량

현재 코드에는 종목별 공유 시세 테이블, 5분 신선도 검사, 중복 종목 제거, 요청당 최대 40종목, DB 기반 공급자 작업 잠금, 기본 90초 보호 시간, 서버 인스턴스 내 토큰 재사용이 있다. 이는 초기 보호 장치이며 여러 사용자 요청을 공정하게 모아 처리하는 중앙 수집 큐는 아니다. 한 사용자의 작업이 다른 사용자의 갱신을 보호 시간 동안 기다리게 할 수 있고, 메모리 토큰 캐시는 다른 서버 인스턴스와 공유되지 않는다.

권장 흐름은 `필요한 종목 집계 → 중앙 수집 큐 → 공급자별 사용량 제어 → 권한에 맞는 공용 시세 저장 → 사용자별 평가`이다. 시세 공유와 계좌/보유 수량 공유를 혼동하지 않는다. 개인 계좌 데이터는 기존 owner/tenant/RLS 경계를 유지한다.

- 같은 종목을 100명이 보더라도 공급자에는 같은 갱신 구간당 한 번 요청하도록 묶는다. 예를 들어 100명 × 20종목이 모두 겹치면 개별 요청 2,000개를 고유 종목 20개로 줄일 수 있다. 이는 설명용 예시이며 실제 호출량은 종목 겹침·공급자 API·FX 요청에 따라 달라진다.
- 공급자/자격 증명별 분산 사용량 제한, 공정한 작업 순서, 중복 요청 병합, 지수 백오프와 무작위 재시도 지연을 둔다. 상한은 계약·계정 설정으로 관리한다.
- 화면 갱신은 시세 수집과 분리한다. 화면은 저장된 최신 유효 시세를 읽고, 수집 작업만 큐에 넣는다. 연결이 끊기면 마지막 유효값과 시각을 표시하며 0으로 바꾸지 않는다.
- 장중 관심 종목, 장 종료 종목, 과거 이력 보강 작업에 서로 다른 우선순위와 갱신 주기를 둔다. 시장 상태는 공급자/거래소 일정에 근거하며 날짜 값을 주말 조건으로 조작하지 않는다.
- 토큰 발급도 중앙에서 중복 방지한다. 서버 비밀 저장소와 암호화·만료 관리를 사용하고 토큰을 브라우저나 공개 시세 캐시에 넣지 않는다.
- 호출 수, 캐시 적중률, 시세 지연, 대기열 나이, 제한 응답, 종목별 미수집률을 관측한 뒤 유료 피드나 스트리밍으로 확장한다. 사용자 수만으로 비용을 추정하지 않는다.
